## 1. Findings

**F-1. The repository generates no letter.** `aso.generate_prior_letter`
(migrations `2026090629`, `2026090634`) writes `# Prior Authorization Request`,
the case number, and a bullet per evidence rationale, and records
`model_name = 'deterministic-template'`. Review, approval, the Affirmation Gate
and signing all bind a hash of that placeholder. web-10 and web-14 in the
active child plan would extend that placeholder path ("deterministic response
composer") rather than replace it.

**F-2. The template work exists only outside the repository.** The 2026-09-10
session produced a MiniJinja package (`spine-pa-templates`: 53 templates, code
catalog, enrichment gates, 12 fixtures, 17 tests), a reference document, a
sample PDF, an engine prototype and ASO-DA-SPEC-001. None of it was in the
repo, in Drive, or on the Mac until this session staged it under
`docs/handoff/document-assembly/`.

**F-3. That package is not integration-ready** (ASO-DA-SPEC-001 §1, six
defects). The two that send people to the wrong work: it reverses ADR-003
(`gap` = "not documented", `void` = "cannot be met"), and `enrich.rs` assigns
evidence states from thresholds — a second, unaudited writer beside the
reassessment command. It also renders a signature from `affirmation.affirmed`
in the payload and accepts free-text clinical fields.

**F-4. The spec's own annotation model conflicts with the frozen web-00
contract.** ASO-DA-SPEC-001 allows an "annotation claim" with no document.
web-00 decision 2 (frozen 2026-09-16) and `letter_claims.document_id NOT NULL`
say an annotation may add attribution only when the claim also points to a
document/page/date; annotation-only assertions are excluded from external
letters. The engine built here follows web-00: `annotation` provenance is
refused in every class that leaves the practice; `attributed_document` is the
form a surgeon's conclusion takes in a letter.

**F-5. D-1 was open; the operator closed it.** The spec recommended a library
linked in-process by `aso-host`. The decision is a self-contained Axum
AG-UI/A2UI agent in the monorepo (roster position 08), with the engine kept
linkable for the desktop/mobile local lane.

**F-6. The active workflow does not know about any of this.** The waypoint is
`runtime-architecture › web-case-to-letter`, next `web-07`; web-10 and web-14
carry "deterministic composer" wording; RA19/RA21 defer Tauri parity. Nothing
in the child plan references a document-assembly agent, `clinical-docs`, a
package digest, or the `draft_document` command.

## 3. Service definition

```
                 web / desktop / mobile shells
                   │  A2UI descriptors over the AG-UI channel (aso.ui.channel)
                   ▼
   ┌──────────────────────────────┐   POST /v1/assemble   ┌──────────────────────────────┐
   │ aso-host                     │ ────────────────────▶ │ aso-document-assembly (08)   │
   │  draft_document command      │ ◀──────────────────── │  Axum 0.8 · AG-UI · A2UI     │
   │  DocumentAssembler port      │   Assembly + surfaces │  loads packages once         │
   │  ONE transaction:            │                       │  calls clinical-docs         │
   │   letters · letter_claims    │                       │  no store · no clock · no    │
   │   letter_qa_results · audit  │                       │  evidence-state writes       │
   └──────────────┬───────────────┘                       └──────────────┬───────────────┘
                  │ reads case_evidence states, sources, annotations      │ in-process on the local lane
                  ▼                                                       ▼
            Postgres (authority)                                   crates/clinical-docs
```

Contract, in the host's terms:

- Input (`AssembleRequest`, camelCase, `deny_unknown_fields`): `kind`,
  `expectedPackageDigest`, `claims[]` (ordinal, text, provenance, criterionId),
  `requiredCriteria[]`, `evidence{criterionId → met|gap|void}`, `context`
  (letterhead, payer, member, request, policy wording, exhibits, contacts —
  no clinical prose), `checks` (policy versions, codes, dated facts).
- Output (`AssembleResponse`): `assembly` (kindKey, kindVersion,
  templateDigest, canonicalMarkdown, renderedClaims[], qa[7], contentSha256)
  and `surfaces[]` (DraftPreviewBlock, QaFindingsBlock, ClaimsManifestBlock,
  HaltMemoBlock when not approvable).
- The host maps: `renderedClaims` → `letter_claims` rows (document_id,
  document_version, page_number, source_quote, source_date, annotation_id);
  `qa` → `letter_qa_results` rows by `qa_check_types.key`; `contentSha256` →
  `letters.content_sha256`; `templateDigest` and kind → `letters.model_name`
  / `model_version` until DA-3 adds a kind reference.
- Signature: `Assembly::render_signed(receipt)` only, from the signing
  command's receipt; templates have no route to a signature.

## 4. What the running workflow must do (the "adjust" in the Codex prompt)

The child plan's ordering — browser first, Tauri parity deferred — stands. The
agent is a server-side service in the local stack, so it fits without moving
the waypoint. Four adjustments:

1. **web-10 / web-14 generation.** The generation command does not compose a
   body in PL/pgSQL. `aso-host` gains a `DocumentAssembler` port; the Postgres
   adapter's `generate_letter` (and the web-14 response variant) collects
   claims from the case's cited sources and annotations, reads
   `case_evidence`, calls the port, and writes letter + claims + QA + audit in
   the one transaction it already opens. `aso.generate_prior_letter` keeps its
   revision guards and idempotency and receives the body, hash and claim rows
   as arguments instead of building them. Purpose → kind: `prior_authorization_request`
   → `pa.initial_request`; `corrected_resubmission` and `clinical_appeal` →
   `pa.denial_response` with `response_mode`.
2. **QA (web-10 acceptance, web-14 acceptance).** `letter_qa_results` rows come
   from the agent's seven findings, not from a second set of checks. A blocking
   failure leaves the letter in `draft` and the `HaltMemoBlock` describes the
   routing (`gap` → surgeon, `void` → coordinator) from committed states.
3. **Local stack (web-16 / web-17).** `docker-compose.yaml` and
   `docker/demo-init.sh` start `aso-document-assembly` on the internal network
   with `ASO_DA_PACKAGES_DIR` pointing at the seed package; `aso-web-server`
   config gains the agent URL and the pinned package digest, and fails startup
   without them, as it already does for Kratos.
4. **Browser surface (web-11 / web-15).** The letter workspace renders the
   four descriptors through the component allowlist; the AG-UI channel is
   opened by `aso.ui.channel`, not by a component. No affirmation surface comes
   from the agent.

Out of the child's scope and left alone: Tauri commands mirroring the routes
(RA19), the in-process `clinical-docs` adapter for the local lane (RA19/RA21),
Flutter descriptors, PDF export (DA-5), the DA-1 port of procedure modules,
schema kind reference (DA-3).

## 5. The uncomfortable part

A cited page that was mis-extracted produces a perfectly formatted wrong
citation; nothing in the agent can see it. The seed package's regulatory
paragraphs have not been read by counsel. And the workflow's frozen web-00
contract predates the agent: if any of its frozen command shapes cannot carry
`expectedPackageDigest` or the claims manifest, that is a contract revision to
record, not a reason to fall back to the placeholder body.

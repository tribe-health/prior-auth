Two letters, one spine

A prior authorization case produces at most two letters: the initial request, sent before the service, and the denial response, sent only if the payer refuses. They are the same argument made at different moments, so they are built from the same parts. Only the sections that describe the moment differ.

Every navy and ember-deep vertebra is the same template in both letters. The ember vertebrae are the only kind-specific sections.

Why the gates matter more for requests

A denial response can only recover a request that already failed. The same gates applied to an initial request stop a submission that would be denied for a documentation gap, before it costs a review cycle. Fixture 12 is that case: its HbA1c is above the policy ceiling, so the letter never renders.

How the engine works

The rule is templates render; Rust decides. Code classification, date arithmetic, threshold comparison, and exhibit integrity are computed once in enrich.rs. The letter and the halt memo read the same enriched context, so they cannot disagree about a case.

Stages 1–4 run in Renderer::enrich. Stage 5 renders letter.md.j2, which picks the halt memo or kinds/<letter.kind>.md.j2.

The renderer

One Environment is built at startup and reused. It is Send + Sync, so a service can share it behind an Arc.

impl Renderer {
    pub fn new(base: &Path) -> Result<Self, Box<dyn Error>> {
        let mut env = Environment::new();
        env.set_loader(path_loader(base.join("templates")));
        // SemiStrict: `{% if missing %}` is allowed; printing a missing value is an error.
        env.set_undefined_behavior(UndefinedBehavior::SemiStrict);
        env.set_trim_blocks(true);
        env.set_lstrip_blocks(true);
        // Partials end with a newline so the orchestrator's blank lines separate sections.
        env.set_keep_trailing_newline(true);
        let catalog = catalog::Catalog::load(&base.join("catalog/cpt_catalog.json"))?;
        Ok(Self { env, catalog })
    }

    pub fn enrich(&self, raw: &str) -> Result<Value, Box<dyn Error>> {
        let mut case: Value = serde_json::from_str(raw)?;
        enrich::enrich(&mut case, &self.catalog)?;
        Ok(case)
    }

    pub fn render(&self, raw: &str) -> Result<String, Box<dyn Error>> {
        let case = self.enrich(raw)?;
        let out = self.env.get_template(ROOT_TEMPLATE)?.render(&case)?;
        Ok(normalize(&out))
    }
}

Letter kinds in Rust

The kind is validated before anything else. Two statuses describe a prior determination and are rejected in initial requests; a request that carries denial reasons is a contract error, not a letter.

/// Letter kinds. Each selects `templates/kinds/<kind>.md.j2`.
const KINDS: &[&str] = &["initial_request", "denial_response"];
/// Statuses that describe a prior determination; meaningless before one exists.
const RESPONSE_ONLY_STATUSES: &[&str] = &["GAP_CLOSED", "DISPUTED"];

The enrichment pass

pub fn enrich(case: &mut Value, catalog: &Catalog) -> Result<(), String> {
    let kind = text(case, "/letter/kind")
        .ok_or("letter.kind is required: `initial_request` or `denial_response`")?
        .to_owned();
    if !KINDS.contains(&kind.as_str()) {
        return Err(format!(
            "unsupported letter.kind `{kind}`; expected `initial_request` or `denial_response`"
        ));
    }
    let program = text(case, "/payer/program")
        .ok_or("payer.program is required")?
        .to_owned();
    if !PROGRAMS.contains(&program.as_str()) {
        return Err(format!("unsupported payer.program `{program}`"));
    }

    let codes = classify_services(case, catalog)?;
    let class = catalog.classify(&codes)?;
    {
        let procedure = obj_mut(case, "/procedure")?;
        let level_count = procedure
            .get("levels")
            .and_then(Value::as_array)
            .map_or(0, Vec::len);
        procedure.insert("family".into(), json!(class.family));
        procedure.insert("family_label".into(), json!(class.family_label));
        procedure.insert("subtype".into(), json!(class.subtype));
        procedure.insert("region".into(), json!(class.region));
        procedure.insert("level_count".into(), json!(level_count));
    }
    default_signing_provider(case)?;
    add_inline_forms(case);

    let mut gate = Gate::default();
    let mut derived = Map::new();
    let mut warnings: Vec<String> = Vec::new();
    let dos = text(case, "/procedure/anticipated_dos").and_then(parse_date);

    check_criteria(case, &kind, &mut gate, &mut derived)?;
    check_code_rules(&codes, &program, catalog, &mut gate);
    check_level_limit(case, &mut gate);

    let bypass = !arr(case, "/clinical/red_flags").is_empty()
        && flag(case, "/policy/red_flag_bypass_allowed");
    derived.insert("red_flag_bypass".into(), json!(bypass));

    check_conservative_care(case, bypass, &mut gate, &mut derived);
    check_imaging(case, dos, &mut gate, &mut derived);
    check_risk_factors(case, dos, &mut gate);
    match class.family.as_str() {
        "facet_intervention" => {
            check_facet(case, class.subtype.as_deref(), &mut gate, &mut derived)
        }
        "spinal_cord_stimulator" => check_scs(case, class.subtype.as_deref(), &mut gate),
        _ => {}
    }
    check_denial_reasons(case, &kind, &mut gate)?;
    check_exhibit_refs(case, &mut gate);
    filter_unverified_references(case, &mut warnings)?;

    derived.insert("warnings".into(), json!(warnings));
    let root = case.as_object_mut().ok_or("case must be a JSON object")?;
    root.insert("derived".into(), Value::Object(derived));
    root.insert("gate".into(), gate.into_value());
    Ok(())
}

Service integration

In the Workbench, the renderer sits behind an endpoint that returns the letter, or 409 with the halt memo so the work queue routes it to staff. The sketch needs one addition, render_context, so the handler reads gate.halt without enriching twice.

// Integration sketch — not in the repository. Axum 0.8 path syntax.
use axum::{Router, extract::State, http::StatusCode, response::IntoResponse, routing::post};
use std::sync::Arc;

async fn draft_letter(State(r): State<Arc<Renderer>>, body: String) -> impl IntoResponse {
    let ctx = match r.enrich(&body) {
        Ok(ctx) => ctx,
        Err(e) => return (StatusCode::UNPROCESSABLE_ENTITY, e.to_string()).into_response(),
    };
    let halted = ctx["gate"]["halt"].as_bool().unwrap_or(true);
    match r.render_context(&ctx) {                      // proposed: render an already-enriched context
        Ok(md) if halted => (StatusCode::CONFLICT, md).into_response(),   // halt memo, internal only
        Ok(md) => ([("content-type", "text/markdown")], md).into_response(),
        Err(e) => (StatusCode::INTERNAL_SERVER_ERROR, format!("{e:#}")).into_response(),
    }
}

pub fn router(r: Arc<Renderer>) -> Router {
    Router::new().route("/cases/{id}/letter", post(draft_letter)).with_state(r)
}

Selection logic

Nine context values decide which templates render. Each is case data validated in Rust or a value Rust computes. No template inspects a code, a date, or a threshold.

Read each lane left to right: the value, its permitted values, and what it selects.

Kind and program compose

letter.kind picks the folder; payer.program picks the file inside it. A Medicare Advantage request imports routing/initial/medicare_advantage; its denial response imports routing/medicare_advantage.

Overlay works for both

The benefit-manager overlay reads route.submission_noun(), so the same partial says "request" or "appeal" without knowing which letter it is in.

Subtype comes from codes

An SCS request with no generator code is a trial. Fixture 11 requests a trial, so the trial-results section never renders.

Red flags reorder the argument

With derived.red_flag_bypass, the cervical module leads with red flags and myelopathy in either letter.

Gates

Gates are fail-closed and identical for both letter kinds. Any item replaces the letter with an internal memo listing each blocking item and its next action.

Clinical semantics

The brand keeps "not met" and "not documented" visually distinct. A VOID is not met: the request itself fails the policy, and documentation cannot cure it (ember). An open GAP is not documented: the evidence may exist but is not on file (grey).

All 18 checks in enrich.rs. A check whose policy threshold is absent from the case is skipped.

Document assembly: the generation and QA contract

Every document the system produces passes through one contract before it leaves the practice: a typed kind, clinical text only as cited claims, QA results the database can hold, and a hash the surgeon affirms. The prior authorization letter is the first of several kinds.

The template system is not integration-ready

The template package built earlier in this session works on its own terms: 12 cases, 17 tests, two letter kinds. Measured against this codebase it breaks two of the four rules the Workbench will not bend (evidence states and clinical authority) and the citation rule in its PHI and compliance section. The worst is first because it sends people to the wrong work.

What survives

The composition model carries over intact: letter kinds, routing modules with a shared macro interface, procedure modules composed from shared evidence partials, the code catalog with family precedence and payer void rules, and the fixture discipline. After DA-1 it becomes the first template package the engine loads, named aso-prior-auth.

What “any medical document” means here

The agent roster in ASO-MVP-001 and the authorization mechanism already name the documents. They fall into six classes, and the class decides the rules a template must follow. Adding a document means adding a kind to a class; adding a class is a design change.

The class that can convict the practice

A generated clinic note becomes a source document, and later letters would cite it. The system would then be citing its own writing as chart evidence. Source-documentation assist can check a note and prompt for required elements; it cannot author findings. That boundary is D-6.

Three kinds of text

A rendered document contains exactly three kinds of text. This is the contract ra-15 defers to when it says no annotation becomes a generated assertion without “the separate generation/QA contract.”

Maps directly onto letter_claims: one source per claim, document or annotation, never both.

Where the guarantee stops

Construction guarantees that every claim carries provenance. It does not stop a template author from typing a clinical fact into boilerplate. Only review closes that channel, which is why template publishing is a governed act (D-4) and why a template used by an approved letter becomes immutable.

pub fn assemble(input: &AssemblyInput) -> Result<Assembly, Error> {
    let by_ordinal: Arc<BTreeMap<u32, Claim>> =
        Arc::new(input.claims.iter().map(|c| (c.ordinal, c.clone())).collect());
    let used: Arc<Mutex<Vec<u32>>> = Arc::new(Mutex::new(Vec::new()));

    let mut env = Environment::new();
    env.set_undefined_behavior(UndefinedBehavior::SemiStrict);
    env.set_trim_blocks(true);
    env.set_lstrip_blocks(true);
    let templates = input.templates.clone();
    env.set_loader(move |name| Ok(templates.get(name).cloned()));

    let (claims_fn, used_fn) = (Arc::clone(&by_ordinal), Arc::clone(&used));
    env.add_function("claim", move |ordinal: u32| -> Result<Value, Error> {
        let c = claims_fn.get(&ordinal).ok_or_else(|| {
            Error::new(ErrorKind::InvalidOperation, format!("claim {ordinal} does not exist; clinical text must come from a claim"))
        })?;
        let mut u = used_fn.lock().expect("claim usage lock");
        if !u.contains(&ordinal) { u.push(ordinal); }
        Ok(Value::from(render_claim(c)))
    });

    let body = env.get_template(input.root)?.render(context! { ctx => input.context })?;
    let rendered_claims = used.lock().expect("claim usage lock").clone();

    let rendered: BTreeSet<u32> = rendered_claims.iter().copied().collect();
    let uncovered: Vec<u32> = input.required_ordinals.difference(&rendered).copied().collect();
    let qa = vec![
        QaFinding { check_key: "unsupported_claim", outcome: QaOutcome::Pass,
                    detail: "Clinical text entered only through claim(); every rendered claim carries provenance.".into() },
        QaFinding { check_key: "criterion_coverage",
                    outcome: if uncovered.is_empty() { QaOutcome::Pass } else { QaOutcome::Fail },
                    detail: if uncovered.is_empty() { "All required claims rendered.".into() } else { format!("Required claims not rendered: {uncovered:?}") } },
    ];

    let mut digest_input = String::new();
    for (name, src) in input.templates { digest_input.push_str(name); digest_input.push('\0'); digest_input.push_str(src); digest_input.push('\0'); }
    let template_digest = hex(&Sha256::digest(digest_input.as_bytes()));
    let mut h = Sha256::new();
    h.update(format!("{}\0{}\0{}\0", input.kind_key, input.kind_version, template_digest).as_bytes());
    h.update(body.as_bytes());

    Ok(Assembly { canonical_markdown: body, rendered_claims, qa, content_sha256: hex(&h.finalize()) })
}

Determinism and hashes

The Affirmation Gate binds a rendered hash, and every submission attachment records a hash and page count at transmission. Both only mean something if rendering is deterministic.

The uncomfortable part

Formatting confers authority it has not earned

The engine makes a claim look exactly as trustworthy as a correct one. If the Chart Extractor attributes a finding to the wrong page, the letter cites the wrong page in perfect form, and no QA check here can see it. The control is ra-16 source preview in front of the approving surgeon.

The letter must describe what happens in the operating room

The mechanism document warns that a letter asserting a wide decompression the operative report does not document is discoverable and reads as a false statement. The request-versus-operative-report reconciliation is an internal work product in this model. If it is deferred, the system can produce exactly the letter that document warns against.

Model prose is the widest channel

If D-2 lands on hybrid, model-written sentences sit between cited claims. Sentence-level marker checks catch an uncited clinical sentence only if “clinical” is detected reliably. That detector is a measurement problem (G-MEASURE), and until it is measured the safe default is templates only.

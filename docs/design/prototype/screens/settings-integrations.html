Connect a system

FHIR R4 is the preferred route. Where a vendor exposes no FHIR endpoint, the fallback is named honestly rather than hidden behind a logo.

What a connection actually needs

Base URL, tenant or practice identifier, client credentials, and the scopes this app requests: patient.read condition.read documentreference.read coverage.read. This app never requests write scopes — it does not write to the chart, and asking for permission it does not need is how integrations get rejected by a security review.

Why this is not automatic

Name plus date of birth is not an identifier. Auto-merging two charts can attach one patient's imaging to another patient's authorization — a error that would travel all the way into a signed letter. The app surfaces the candidate and stops.

What gets pulled

A connection does not import an entire chart. It watches for surgical candidates and pulls only what the authorization workflow needs.

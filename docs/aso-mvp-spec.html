Executive summary

Prior authorization for spine surgery is not one workflow. It is a routing problem wrapped around a documentation problem wrapped around an appeals problem, and the three fail in different ways.

The routing problem: the entity that decides is usually not the entity on the insurance card. Cigna spine goes to eviCore. Humana musculoskeletal goes to Cohere. Several Blues and Centene lines go to TurningPoint or Carelon. A submission sent to the payer instead of the delegated vendor does not get denied — it sits, and the statutory clock never starts.

The documentation problem: criteria converge on a small set of documentable facts — imaging graded moderate-or-worse correlating to exam, weeks of supervised conservative care with dates, instability measured in millimetres and degrees, functional scores, tobacco and psych gates — and diverge at exactly the points where a spine practice loses cases. Aetna will not authorize lumbar fusion for degenerative disc disease alone. Carelon wants three of seven provocative tests for sacroiliac fusion and 75% relief from two separate injections; Aetna wants three of five and 70%. Two-level cervical arthroplasty is covered only with a device FDA-approved for two levels.

The appeals problem: per the 2024 AMA survey, 81.7% of appealed prior authorization denials are overturned in whole or in part. That number is the entire business case. It says most initial denials are not clinically robust, and that a practice which appeals systematically rather than selectively recovers most of what it loses — but only if the cost of appealing falls far enough to make appealing every eligible denial rational.

What this MVP is actually for

Not "AI writes letters." The letter is one artifact in a state machine that runs for weeks, crosses four or five channels, and loops. The system's job is to hold the case — know where it is, what it needs, who is holding it, what clock is running, and what the next action is — and to make each loop cheap enough that the practice always takes it.

The five properties that define the build

  1. Administering-entity resolution comes first. Everything downstream — criteria set, channel, peer-to-peer line, appeal path, timer set — keys off which vendor administers this benefit for this member, not which logo is on the card.
  2. Every generated assertion carries a source citation with document, page, and date. This is a False Claims Act control, not a UX flourish.
  3. A physician affirmation gate stands between drafting and transmission, and is enforced as a dependency in the plugin runtime rather than as a conditional in the render path.
  4. Channels are adapters behind one interface. Fax, portal, phone, EDI, and FHIR are interchangeable at the dispatch boundary, which is what lets the FHIR path land in 2027 without a rewrite.
  5. Every four to six weeks something ships that changes a working day. No release is infrastructure-only.

A deployment posture change, stated plainly

ASO-ARCH-001 specified a local-first Tauri desktop application: PHI on one machine, no hosted store, minimal Security Rule surface. That posture was correct for a single surgeon drafting letters.

It does not survive contact with this workflow. A prior authorization coordinator, a surgery scheduler, a biller, two surgeons, and a physician assistant all touch the same case. They need shared state, concurrent access, a work queue that means the same thing to everyone, and inbound fax that arrives somewhere other than one person's laptop. Local-first cannot deliver that.

The MVP therefore deploys as a practice-boundary system: Fabric services running on a single-tenant node the practice controls — either an on-premise box in the Southlake office or a dedicated single-tenant cloud instance in a US region — with Tauri desktop, Flutter mobile, and React web clients connecting to it.

Why this still satisfies the constraints

PHI at rest stays inside the practice boundary and inside the United States, which is what Texas SB 1188 requires as of January 1 2026. The only PHI egress is to a BAA-covered inference endpoint with zero data retention, and that egress is gated by Cedar policy rather than configuration. The Security Rule surface is larger than the laptop version and has to be documented and risk-assessed properly — that is a real added cost and it should be priced into Phase 0 rather than discovered in Phase 3.

Two integration facts worth deciding early

Telnyx must sign a BAA. Every inbound determination letter transits their fax infrastructure. If they will not sign, the fax channel needs a different vendor and that changes R3.

Portal automation is a terms-of-service question, not a technical one. Scraping and RPA against payer portals commonly violates their terms. The design assumption is portal-assist — the system assembles the packet, pre-fills what it can, deep-links the coordinator into the right screen, and captures the reference number on return. Full portal automation only where a sanctioned API exists.

Autonomy legend

Autonomous — acts without a human; outputs are facts, not clinical assertions. Review — a human sees the output before it is used downstream, but no signature is required. Assist — the agent prepares, a human executes the irreversible step. Gated — output cannot leave the system without a physician affirmation. Human only — the agent renders the decision surface; the decision is not the agent's to make.

User stories

Dr. Kevin James — surgeon

  • US-01 As the surgeon, I want a criteria matrix showing met / not met / not documented with a source citation on every row, so that I can affirm in under a minute and defend it later.
  • US-02 As the surgeon, I want the letter drafted from arguments I authored once, so that I stop re-explaining my reasoning on every case.
  • US-03 As the surgeon, I want a peer-to-peer briefing that crosswalks the vendor's published criteria against my chart evidence, so that I walk into the call with their own standard in front of me.
  • US-04 As the surgeon, I want to be told when a case is medically supportable but administratively incomplete, so that I do not spend a P2P slot on a records problem.
  • US-05 As the surgeon, I want to review and affirm from my phone between cases, but I accept that signing happens at a desktop.

Nathan Mahanirananda — physician assistant

  • US-06 As the PA, I want to see which criteria elements are missing for this specific payer while the patient is still in clinic, so that I document them now rather than chase them later.
  • US-07 As the PA, I want the system to tell me the exact threshold — twelve weeks, three of five provocative tests, seventy-five percent relief across two injections — rather than "insufficient conservative care."

Prior authorization coordinator

  • US-08 As the coordinator, I want a single queue ordered by regulatory deadline and surgery date, so that I stop deciding what to work on from memory.
  • US-09 As the coordinator, I want the correct administering entity resolved for me, so that I stop sending eviCore packets to Cigna and losing two weeks.
  • US-10 As the coordinator, I want inbound faxes parsed and attached to the right case automatically, so that I stop being the routing layer.
  • US-11 As the coordinator, I want denial reasons classified as fix-and-resubmit versus appeal, so that I know within a minute whether this needs a surgeon.
  • US-12 As the coordinator, I want to be warned before a statutory clock runs out, not after.
  • US-13 As the coordinator, I want the appeal drafted with the criteria crosswalk already in it, so that appealing every eligible denial becomes affordable.

Surgery scheduler

  • US-14 As the scheduler, I want authorization status and validity window visible on the board, so that I stop asking.
  • US-15 As the scheduler, I want to be blocked from booking a date beyond the authorization's expiry, with an override that records who overrode it.
  • US-16 As the scheduler, I want to know the moment an approval lands so I can fill a slot the same afternoon.

Biller and administrator

  • US-17 As the biller, I want authorized CPTs and the authorization number attached to the case, and an alert when operative codes diverge.
  • US-18 As the administrator, I want approval rate by physician, service, and plan, so that I can pursue gold-card exemptions and contest rescissions with the underlying claim list.
  • US-19 As the administrator, I want denial and overturn rates by payer, so that I can hold a payer relationship conversation with evidence.
  • US-20 As the administrator, I want AI-use disclosures and onshore-storage attestations recorded, so that SB 1188 and TRAIGA compliance is evidenced rather than asserted.

Patient

  • US-21 As the patient, I want to know the one thing I need to do next, without clinical detail arriving by text message.
  • US-22 As the patient, I want to know that my authorization is moving, so I stop calling the office to ask.

One interface convention across all six

A source citation chip sits adjacent to the claim it supports, never in a footnote block. An assertion rendered without one is a bug, not a styling choice — it means something reached the screen that cannot be traced, and that is the exact failure the False Claims Act exposure runs through.

The line that carries the case

R4 is where the money is, and it is not a labour-savings argument. At 6 denials a month and an appeal rate near 50%, roughly three appealable denials per month are currently abandoned. At an 81.7% overturn rate, about 2.5 of those would have been won. If a spine case contributes conservatively $3,000–6,000 in professional collections, abandoning three appeals a month is a five-figure monthly loss — and the reason they are abandoned is that each one costs four hours.

Drive that cost to forty minutes and appealing every eligible denial becomes the obvious choice rather than a judgment call. That is the whole mechanism.

The honest ceiling

Gold-carding applies only to TDI-regulated fully-insured plans, which per the Texas Medical Association cover about 20% of Texans. Even a perfect exemption record leaves roughly four-fifths of the practice's prior authorization volume untouched. Gold-carding is a real prize; it is not the strategy.

Holding the four-to-six week cadence

The cadence is not a scheduling preference. It is the mechanism that keeps the project honest, because a release that must change a working day cannot hide behind infrastructure progress.

  1. Every release names the person whose day changes. If no persona can be named, the work is re-scoped before it is committed. This is why R0 ships a queue rather than only a data model.
  2. Plugins drop into a running shell. After R0 the shell is not rebuilt. Each release adds fibers that activate when their coeffects are provided, so a release is a deployment of plugins rather than a replacement of the application.
  3. Vertical slices, not layers. R1 covers three CPTs against three entities completely rather than all CPTs partially. Coverage widens by adding criteria packs, which is configuration and data, not code.
  4. The manual path is never removed. Every automated route has a human fallback that stays. This is what makes a mid-release rollback survivable and what handles the outside records that will never arrive through an API.
  5. Exit criteria are behavioural, not architectural. "Fiber lifecycle implemented" is not an exit criterion. "An inbound determination attaches to the right case without human routing on 90% of faxes" is.
  6. Measurement continues from R0 onward. The same instruments that establish the baseline stay on. A release that does not move a tracked metric gets examined rather than celebrated.
The release that will be tempting to skip

R0 produces no automation and will feel like overhead. It is the only release that makes every subsequent claim in this document checkable. Skip it and the ROI table stays a set of assumptions permanently, and there is no way to tell whether R4 worked.

What would make this project the wrong one

If the measured first-pass approval rate is already above 90% and denials are rare, the appeal engine has little to recover and the whole case rests on labour savings — which a much simpler tool could deliver. If the coordinator is spending fifteen hours a month rather than ninety-nine, the same conclusion follows. R0 exists to find out, and the answer should be allowed to be no.

# Spec Delta

## Purpose

Defines PatientGPT's iOS on-device chat engine, where it runs, and how the app
behaves where it cannot run.

## ADDED Requirements

### Requirement: iOS streams a local reply where MLX can run
On a physical iPhone and on an Apple-silicon Mac running the iOS app as "Designed
for iPad", with UAR not configured and a `ready` MLX chat model, a `local`
onboarding run SHALL stream a reply generated by that model as the `local-chat`
event sequence.

#### Scenario: Designed for iPad on the Mac
- **WHEN** a user sends an onboarding message in the iOS app running on the Mac destination
- **THEN** the reply appears incrementally and the run ends with `RUN_FINISHED`

#### Scenario: Physical iPhone
- **WHEN** a user sends an onboarding message on a physical iPhone
- **THEN** the reply appears incrementally and the run ends with `RUN_FINISHED`

### Requirement: The simulator states that it has no chat engine
An iOS simulator build SHALL register no chat engine. Its `local` runs SHALL be
refused with `engine_unavailable` and the message SHALL state that the on-device
chat model does not run in the iOS simulator.

#### Scenario: Local run in the simulator
- **WHEN** a user sends an onboarding message in the iPhone 17 simulator
- **THEN** the app shows that the on-device chat model does not run in the simulator, and no reply text is shown as if from the model

### Requirement: The engine is registered once, before any run
The Runner SHALL register the engine with the Rust core during app launch, before
the Flutter UI can start a run. A second registration SHALL be ignored and logged.

#### Scenario: Run immediately after launch
- **WHEN** a run is started as soon as the home view appears
- **THEN** the run reaches the engine, or is refused with `model_not_installed` if no model is ready, and is never refused with `engine_unavailable` on a device build

### Requirement: Engine failures end the run and leave the app usable
If the engine fails to load the model or generation fails with an error, the run
SHALL end with `RUN_ERROR` and the app SHALL remain usable. An operating-system
termination for memory is outside this guarantee and is recorded, not masked.

#### Scenario: Missing file at load time
- **WHEN** a required model file is deleted after the entry became `ready`
- **THEN** the load-time catalog check refuses the run with `model_not_installed` before the engine loads, and the conversation stays open

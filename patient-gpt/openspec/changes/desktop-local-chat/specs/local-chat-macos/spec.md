# Spec Delta

## Purpose

Defines the macOS desktop's on-device chat engine: it loads the verified Qwen3
model and streams one reply per onboarding turn without UAR.

## ADDED Requirements

### Requirement: macOS desktop streams a local reply with UAR absent
On macOS with Apple Silicon, with `PATIENTGPT_UAR_MODE=none` and a `ready` chat
model, a `local` onboarding run SHALL stream a reply generated by that model
through the Tauri channel as the `local-chat` event sequence.

#### Scenario: First local reply on desktop
- **WHEN** a user sends "What do you need from me to set up this device?" in an onboarding conversation in the Tauri window
- **THEN** the reply text appears incrementally in the thread and the run ends with `RUN_FINISHED`

### Requirement: Reasoning text is not shown as the reply
The engine SHALL format turns with the model's chat template with thinking
disabled, and SHALL NOT emit model reasoning blocks as `TEXT_MESSAGE_CONTENT`.

#### Scenario: No think tags in the thread
- **WHEN** a local reply completes
- **THEN** the assembled reply text contains no `<think>` or `</think>` markers

### Requirement: Generation is bounded and cancellable
A reply SHALL stop at a fixed maximum of new tokens. When `cancel_operation` is called
or the shell drops the stream, generation SHALL stop at the next token and release
the engine for the next run.

#### Scenario: Cancelled run frees the engine
- **WHEN** the user leaves the conversation while a reply is streaming and then starts a new onboarding run
- **THEN** the new run starts and streams without waiting for the abandoned reply to finish

### Requirement: Other desktop targets have no engine
A desktop build for a target other than macOS on Apple Silicon SHALL register no
chat engine, and its `local` runs SHALL be refused with `engine_unavailable`.

#### Scenario: Intel macOS build
- **WHEN** a debug desktop build on the Intel Mac receives a `local` onboarding run and an `embed` call
- **THEN** both are refused with `engine_unavailable`

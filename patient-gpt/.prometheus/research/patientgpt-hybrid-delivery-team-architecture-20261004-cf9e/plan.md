# PatientGPT team and delivery research plan

## Query
Create an effective development team for the requested PatientGPT hybrid architecture and two-hour usable-flow delivery cadence, including product management, team leadership, creative direction, design, and UAR agent-building expertise.

## Sub-questions
- What storage and shared-domain seams preserve one clinical source of truth across browser PGlite, desktop embedded SurrealDB 3.3.0, and Axum/Postgres with Flint Forge and Fabric?
- How do Kratos, Flint Gate, and the existing Envoy Gateway compose identity and authorization without inventing Oathkeeper equivalence or trusting client-side clinical checks?
- Which UAR agent-definition, tool-governance, AG-UI event, and A2UI registry contracts must the dedicated agent expert own?
- How can all React UI code be shared by web and Tauri while preserving custom titlebar behavior, kebab-case TypeScript 7.0 files, and Flutter mobile parity?
- Which installed design and framework skills fit independent creative-director, design-expert, web, desktop, and Flutter responsibilities?
- How should phase scope and task handoffs yield visible complete flows every 120 minutes with local web builds each increment, full web/Tauri builds every second increment, and tests only after a whole phase is implemented?
- What deployment/documentation roles and constraints are needed for know-me Kubernetes, existing Envoy, GitHub Actions, Docusaurus/Pages, and the monorepo About URL?
- Which native harness/model/export capabilities are actually configured, and what remains source-only or unverified?

## Search strategy
Use isolated read-only research workers for local Flint/storage/identity, UAR/protocol registry, and UI/platform/docs evidence. Each worker records its own source IDs and retrieval evidence. Use current Context7 resolution and scoped queries before official web sources; prioritize actual source code over stale READMEs and do not infer runtime certification. Root inspects team/cadence tooling and model policies. Search terms: SurrealDB Rust embedded local engine; PGlite sync; Kratos Envoy ext_authz; UAR component registry AG-UI A2UI; Tauri custom titlebar; Flutter responsive architecture; Docusaurus GitHub Pages monorepo. Local evidence includes exact paths, checked revisions, and limitations.

## Stages and bounds
Stages 01 through 10, full scale, driven through run-research.sh checkpoint mode. Stage 05 source verification precedes adversarial review of the completed report. Three parallel workers maximum, no nested research workers. Research scope is the implementation/team decision, not a general technology survey. Confidence threshold 0.7 for directly supported claims; uncertain integration and version claims stay labelled. No fixed token budget was requested; keep retrieval focused and stop after the questions are answered or gaps are explicit.

## Deliverables
A citable persistent research package, contradiction ledger, installed project team with native export receipts, local skill bindings and Impeccable product context, and a cadence-ready vertical-flow plan with honest activation prerequisites. No application implementation, live UAR activation, cluster mutations, GitHub publishing, or invented build commands.

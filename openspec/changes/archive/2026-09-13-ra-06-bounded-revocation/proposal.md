## Why

The runtime assessment identifies a missing integration or invariant in this area. Expire and revoke active replica delivery within a measured bound is required to achieve the phase's authorized, scoped runtime outcome.

## What Changes

Establish one enforceable revocation contract across cached identity, minting, open responses and reconnects. Clinical commands freshly validate authority. Implement the server logout result consumed by browser logoutPending; retain original session linkage and stop streams when revalidation cannot succeed. Connect the completed RA-03 signing and reassessment command contracts to reachable React controls, and project revocation into the same command UI so protected actions lock immediately without optimistic clinical state.

The server contract starts at the authoritative ASO membership commit, durable session-denial commit or verified expiry instant. ASO records replayable authority events and logout retry intent; Gate rechecks the current ASO authority fence for protected authorization; FRF holds that authority through response-body production. The measured boundary ends at the final protected frame produced by the server or cancellation that prevents the next frame. It does not claim when an operating-system buffer, proxy or client receives bytes.

The access boundary accepts a later server-verified session, but the public Kratos flow that obtains it remains in `ra-12-public-auth-startup`. Durable draft persistence and same-identity recovery remain in `ra-13-epoch-logout-and-drafts` after the G-DATA decision. RA06 keeps its replica graph disposable and makes no draft-recovery claim.
